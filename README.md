# Pinecone Memory Bot

Telegram-бот с персональным ассистентом на Haystack. Текстовые сообщения обрабатывает агент: он отвечает по-русски, при необходимости вызывает инструменты и опирается на короткую историю чата и похожие прошлые реплики этого пользователя из Pinecone. Фотография скачивается ботом, путь к файлу передаётся агенту, а временный файл удаляется после ответа.

## Возможности

* ответы в Telegram через Haystack Agent и модель `gpt-5.4-nano`;
* текущая погода по названию города через Open-Meteo;
* случайный факт о кошках через Cat Facts API;
* разбор фотографии: есть ли на ней собака, окрас и предполагаемая порода;
* долговременная память этого пользователя: текст его сообщений сохраняется в Pinecone;
* короткий контекст чата для уточнений вроде «а завтра?»;
* команды `/start`, `/help` и `/clear`.

## Как это работает

```text
Telegram
   │
   ├── текст ──────────────► ask_agent()
   │                              │
   │                              ├── найти до 5 записей этого user_id
   │                              │     со score не ниже порога
   │                              ├── добавить последние реплики чата
   │                              ├── сохранить сообщение пользователя
   │                              └── Haystack Agent
   │                                     ├── weather_tool
   │                                     ├── cat_fact_tool
   │                                     └── dog_image_analyzer
   │
   └── фото ───────────────► скачать файл во временный путь
                                  │
                                  └── ask_agent(подпись, путь к файлу)
                                        │
                                        └── dog_image_analyzer
                                  удалить временный файл
```

Поиск по Pinecone выполняется до записи текущего сообщения, поэтому только что отправленный текст не занимает место в контексте. В выборку попадают записи с `user_id` этого пользователя и score не ниже `SIMILARITY_THRESHOLD`. Последние реплики чата хранятся в памяти процесса и помогают понять короткое уточнение. Бот скачивает фото, передаёт путь анализатору через агента и удаляет временный файл после ответа.

## Стек

| Компонент | Версия | Роль |
| --- | --- | --- |
| Python | 3.12 | язык |
| haystack-ai | 3.3.0 | агент, чат-модель, embeddings |
| pinecone-haystack | 6.4.1 | хранилище и поиск документов |
| pinecone | 10.0.0 | клиент векторной базы |
| pyTelegramBotAPI | 4.37.0 | Telegram |

| python-dotenv | 1.2.4 | переменные окружения |

Модель ответов и разбора изображений — `gpt-5.4-nano`. Embeddings — `text-embedding-3-small`, размерность 1536. Запросы к OpenAI идут через `OPENAI_BASE_URL`.

### `app/telegram_bot.py`

Точка входа бота.

* `/start` — приветствие и список возможностей;
* `/help` — примеры запросов;
* `/clear` — удаление документов этого пользователя и коротких реплик чата;
* текст — передаётся в `ask_agent` вместе с `user_id` и `chat_id`;
* фото — скачивается в `/tmp`, путь и подпись уходят в `ask_agent`, файл удаляется.

### `app/agent.py`

Собирает Haystack `Agent` и функцию `ask_agent`.

`ask_agent` сначала ищет до пяти похожих реплик этого `user_id`, затем сохраняет текущее сообщение пользователя. К запросу добавляются последние реплики чата и блок «Контекст из памяти пользователя». Агент сам решает, вызывать ли погоду, факт о кошках или анализ изображения. Ответ ассистента сохраняется только в кратковременной памяти текущего процесса. Фотография без подписи не сохраняет в Pinecone искусственный текст: сохраняется только текст, реально отправленный пользователем.

### `app/memory.py`

Класс `PineconeMemory` работает с индексом из `PINECONE_INDEX_NAME` и namespace `haystack-memory`.

* `save_message` — embedding и новый документ с UUID. В metadata есть `type`, `user_id` и `created_at`;
* `search` — ближайшие документы этого `user_id`, у которых score не ниже порога;
* `clear` — удаление документов этого `user_id`.

Каждое непустое сообщение сохраняется отдельно. Похожий текст не перезаписывает старую запись. Записи без `user_id`, оставшиеся от прежней версии, в поиск и в `/clear` не попадают.

Для работы проекта должен существовать Pinecone-индекс с размерностью 1536 и метрикой cosine. Параметры подключения берутся из `.env`.

### `app/tools.py`

| Инструмент | Вход | Источник | Кто вызывает |
| --- | --- | --- | --- |
| `WeatherTool` | город | Open-Meteo | агент |
| `CatFactTool` | без аргументов | catfact.ninja | агент |
| `DogImageAnalyzerTool` | путь к файлу | `gpt-5.4-nano` | агент |

Погода: координаты города, затем температура, ощущаемая температура, код погоды, влажность и ветер. Факт о кошках возвращается одной строкой. Анализатор изображения смотрит локальный файл и отвечает по-русски, есть ли на фото собака.

### `test_agent.py`

Проверяет текстовый контур без Telegram: спрашивает текущую погоду в Москве, затем уточняет «А завтра?» в том же чате. Оба запроса пишутся в Pinecone от имени `test-agent`.

### `test_memory.py`

Проверяет разделение памяти. Сохраняет фразу для пользователя A, ищет её другим запросом, убеждается, что пользователь B её не видит, и очищает только записи A.

### `test_tools.py`

Отдельно проверяет инструменты, без агента и без Telegram:

* `CatFactTool` — запрос случайного факта о кошках;
* `DogImageAnalyzerTool` — разбор локальной фотографии, если путь к файлу передан аргументом.

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## Переменные окружения

```bash
cp .env.example .env
```

```env
PINECONE_API_KEY=your_pinecone_api_key
PINECONE_INDEX_NAME=pinecone-memory-bot

OPENAI_BASE_URL=https://api.proxyapi.ru/openai/v1
OPENAI_API_KEY=your_proxyapi_key
EMBEDDING_MODEL=text-embedding-3-small

TELEGRAM_BOT_TOKEN=your_telegram_bot_token

SIMILARITY_THRESHOLD=0.5
```

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `PINECONE_API_KEY` | да | ключ Pinecone |
| `PINECONE_INDEX_NAME` | да | имя индекса |
| `OPENAI_API_KEY` | да | ключ для чата и embeddings |
| `OPENAI_BASE_URL` | да | базовый URL API |
| `EMBEDDING_MODEL` | нет | модель embeddings, по умолчанию `text-embedding-3-small` |
| `TELEGRAM_BOT_TOKEN` | да для бота | токен от BotFather |
| `SIMILARITY_THRESHOLD` | нет | минимальный score для контекста, по умолчанию `0.5` |

`test_agent.py` токен Telegram не использует. Ключи остаются в `.env`; в репозиторий попадает только `.env.example`.

## Запуск

Проверка агента из корня проекта:

```bash
python test_agent.py
```

Проверка изоляции памяти:

```bash
python test_memory.py
```

Отдельная проверка `CatFactTool` и `DogImageAnalyzerTool`:

```bash
python test_tools.py
python test_tools.py path/to/photo.jpg
```

Без пути к файлу проверяется только `CatFactTool`. `DogImageAnalyzerTool` в этом случае пропускается.

Пример вывода:

```text
Вопрос: Какая сейчас погода в Москве?

Ответ агента:
Сейчас в Москве: 8.9°C, ощущается как 7.7°C. Пасмурно, влажность 86%, ветер 2.9 км/ч.
```

Запуск бота:

```bash
python -m app.telegram_bot
```

В консоли:

```text
Telegram-бот запущен...
```

В Telegram:

* «Какая сейчас погода в Москве?» — агент вызывает `weather_tool`;
* «А завтра?» — короткий контекст чата сохраняет город предыдущего вопроса;
* «Расскажи интересный факт о кошках» — агент вызывает `cat_fact_tool`;
* фотография — агент вызывает `dog_image_analyzer`, временный файл удаляется;
* `/clear` — очистка документов этого пользователя, а не всего namespace.

## Безопасность

`.gitignore` исключает окружение, секреты и кэш:

```gitignore
.venv/
.env
__pycache__/
*.pyc
.DS_Store
```

Реальные ключи и токен бота не должны попадать в Git. `/clear` удаляет документы текущего пользователя. Короткие реплики чата живут в процессе бота и пропадают после перезапуска.
